# aivo 要件定義書

- 文書ID: AIVO-REQ-001
- バージョン: v0.1 (Draft)
- 更新日: 2026-10-23
- 対象: ローカルAI音声アシスタント
- ステータス: 仕様案。機能・性能は未実装／未検証

## 1. 目的と成功条件

aivoは、ユーザーがマイクで話しかけると、端末内の音声認識・LLM・音声合成により自然な音声で応答する個人向けアシスタントである。ChatGPT Voice Modeに近い体験を**段階的**に目指す。ただし製品やモデルの完全再現は目的としない。

### 目的
1. 日本語中心の音声対話を実現する。
2. モデル取得後はクラウド推論APIなしで会話できる。
3. 会話中の応答遅延を定量的に改善できる。
4. モデルや推論バックエンドを差し替えられる。

### 成功条件
- MVP (v0.1): ネットワークを切断した状態で、少なくとも10ターン連続して音声入力→音声応答が成立する。
- 次期版 (v0.2): 応答のストリーミング化と割り込みに対応し、後述の遅延目標に到達する。

## 2. 前提・スコープ

- 初期対象: ローカルPC（Windows 11 / Ubuntu 24.04）、PC内のWeb UIを使用。
- 参考評価構成: NVIDIA RTX 3060 Ti 8GB VRAM、RAM 16GB以上。**この構成で性能・同時常駐が保証されるものではない**。CPU実行・別GPUにも対応を目指す。
- 使用言語: 日本語を必須、英語を比較・追加対象とする。
- 初回インストール、パッケージ導入、モデルのダウンロードには通信が必要となり得る。
- オフライン保証の対象は**初期構築完了後の音声対話**とする。
- MVP対象外: スマートフォンからの遠隔アクセス、クラウド同期、画像・動画入力、カレンダー連携、PC操作、ウェイクワード、話者識別。

## 3. 優先度定義

- **P0**: MVPに必須。最初のリリースで受け入れテストを満たす。
- **P1**: ChatGPT Voice Modeに近づけるための次期版機能。
- **P2**: 将来拡張。初期設計では拡張余地のみ確保する。

## 4. 機能要件

| ID | 優先度 | 機能 | 仕様・受け入れ基準 |
| --- | --- | --- | --- |
| FR-01 | P0 | 音声入力 | PCのマイクを選択し、開始・停止できる。入力デバイス異常を画面に表示する。 |
| FR-02 | P0 | 発話検知 (VAD) | 音声区間を検出し、無音期間でターンを確定する。閾値を設定可能にする。 |
| FR-03 | P0 | 日本語STT | 日本語音声をテキストに変換し、認識結果をUIに表示する。 |
| FR-04 | P0 | ローカルLLM | ローカルOllamaを用いて回答を生成し、外部推論APIを呼ばない。 |
| FR-05 | P0 | 日本語TTS | LLMの回答を日本語音声に変換し、クライアントで再生する。 |
| FR-06 | P0 | 会話文脈 | セッション内の過去ターンを保持し、代名詞や直前の質問を解決できる。 |
| FR-07 | P0 | 会話UI | ユーザーとAIのテキスト、Listening/Processing/Speaking/Idleを表示する。 |
| FR-08 | P0 | セッション制御 | 開始・停止・新規会話の作成ができ、停止後に音声が残って再生されない。 |
| FR-09 | P0 | 処理時間計測 | VAD/STT/LLM(TTFTと生成時間)/TTS/初回再生までの時間を追跡する。 |
| FR-10 | P1 | 発話割り込み | AI再生中にユーザーが話し始めたら音声再生と未完了の生成を止める。 |
| FR-11 | P1 | ストリーミング応答 | LLMトークンを分節化して逐次TTSへ送り、生成完了を待たずに再生する。 |
| FR-12 | P1 | 保存・削除 | 設定で会話履歴の保存を有効化し、一覧表示・個別削除・一括削除ができる。 |
| FR-13 | P1 | モデル・音声設定 | STT/LLM/TTSの選択、音声種別、読み上げ速度などを変更できる。 |
| FR-14 | P1 | エコー対策 | スピーカー再生音の再認識・自己応答ループを実用上防ぐ。 |
| FR-15 | P1 | 連続対話 | ボタンを押し直さず複数ターンを継続できる。 |
| FR-16 | P2 | 多言語 | 英語での認識・応答を拡張し、言語を自動判定できる。 |
| FR-17 | P2 | ツール連携 | ファイル検索など権限を限定したローカルツールを実行できる。 |
| FR-18 | P2 | モバイルUI | 同一LAN内のスマートフォンから接続できる（認証・TLSを前提）。 |
| FR-19 | P2 | 推論バックエンド | llama.cpp / OpenVINOなどに切り替え可能な構造とする。 |

### 例外・失敗時の動作
- マイク拒否／デバイス未接続: 原因をUIに表示し、再試行可能。
- STTが空文字を返す: 不要なLLM呼び出しを行わず、次の発話を待つ。
- LLM／TTSのタイムアウト: ターンをエラー終了として回復可能な待機状態に戻す。
- ユーザーが停止／割り込み: 古いセッションから音声が再生されないようにする。
- モデル未導入: 必要なモデル名、取得手順（ネット接続が必要）を表示する。

## 5. 非機能要件

| ID | 要件 | 目標・検証方法 |
| --- | --- | --- |
| NFR-01 | 完全ローカル推論 | 初期準備後、ネットワーク切断時にP0フローが成立。通信監視で外部推論APIへのアクセスがない。 |
| NFR-02 | 初回音声応答時間 | v0.2目標: ユーザー音声終了からAI音声再生開始まで P50 ≤ 3秒、P95 ≤ 6秒。 |
| NFR-03 | 割り込み応答 | v0.2目標: ユーザー発話開始からAIの再生停止まで P95 ≤ 500ms。 |
| NFR-04 | 音声認識品質 | 日本語評価セットでCER ≤ 10%を**暫定目標**。録音環境や発話者を記録する。 |
| NFR-05 | 安定性 | 60分連続試験で異常終了／OOMなし（v0.2の目標）。MVPでは10ターン連続試験。 |
| NFR-06 | プライバシー | 録音は既定で永続保存しない。履歴保存はユーザー選択制。外部送信なし。 |
| NFR-07 | セキュリティ | 既定で127.0.0.1にバインド。LAN開放時は認証・適切なTLS・接続制御を必須にする。 |
| NFR-08 | 可観測性 | 各ターンの段階別レイテンシ、エラー、モデル名、実行デバイス、メモリを記録。音声本体は記録しない。 |
| NFR-09 | 移植性 | Windows 11 / Ubuntu 24.04で再現できる構築手順と動作確認項目を提供。 |
| NFR-10 | リソース | 8GB VRAM級の参照構成で同時常駐可否を実測し、必要に応じCPUへSTT/TTSを分離する。 |

### レイテンシ測定の定義
- **開始点**: ユーザーの実際の最終発声音の時刻（マイク取得側の単調時計基準）。
- **終了点**: AI応答の最初のPCMフレームがクライアントで再生開始された時刻。
- VAD終了判定の待機時間、ネットワークローカル転送、STT、LLM、TTSを**すべて含む**。
- Warm状態で100ターン以上の固定ベンチマークを実行し、P50/P95を報告。コールドスタートは別途測定。
- 割り込みはユーザー発話開始から**音声出力停止**までを測定（生成キャンセル完了は別指標）。
- 指標は開発目標であり、現時点での達成値ではない。

## 6. ユーザーシナリオ（E2E受け入れ）

### AT-01: オフラインの基本会話（MVP）
**Given** モデル・パッケージの導入が完了し、ネットワークが切断されている。  
**When** アプリを起動して日本語で10ターン話す。  
**Then** 全ターンでユーザー発話の表示、AIのテキスト応答、音声再生が成立し、クラウドAPIを使わない。

### AT-02: 会話文脈（MVP）
**Given** 「私の好きな色は青です」と話した。  
**When** 「さっきの色は？」と尋ねる。  
**Then** AIが当該セッションの文脈を利用して回答を生成する（モデルの確率的変動を考慮し複数回評価する）。

### AT-03: エラー回復（MVP）
**Given** マイクアクセスが拒否された。  
**When** 会話開始を試みる。  
**Then** エラーが表示され、許可後の再試行で復旧する。

### AT-04: ストリーミング（v0.2）
**When** 長い回答を要求する。  
**Then** LLM全生成終了前に、意味のある最初の発話部分の音声再生が始まる。

### AT-05: 割り込み（v0.2）
**Given** AIの音声が再生中。  
**When** ユーザーが話し始める。  
**Then** AI出力が停止し、古い音声が後から再生されず、新しい質問を受け付ける。

## 7. 除外・リスク・決定待ち

- 声質、感情、同時発話の自然さはSTT→LLM→TTSではChatGPTの音声対話と同等とは限らない。
- 日本語TTSの品質、推論速度、ライセンス、声の使用条件を採用前に評価する。
- モデルのサイズとVRAM使用量は異なる。LLMのKV cache、STT/TTS、WebRTC等を含むピークを測る。
- オフライン要件に反して、フレームワークがクラウドAPIを暗黙利用していないことをネットワーク切断で検証する。
- ライセンス・サードパーティモデル利用条件を確認するまで、アプリ本体のライセンス選定を保留する。
- 発話中の音声原本保存は初期スコープ外。
